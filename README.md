# Threads 文章與留言蒐集器（含 Gemini 趨勢分析＋使用者分析）

用和 Dcard 工具相同的 Tkinter 介面，改抓 Threads（threads.com / threads.net）
的公開文章與回覆，並可分析指定帳號的寫作與互動風格。

**全部模式都是免費的，沒有任何要錢的爬蟲服務。**

## 功能

- **蒐集來源**：三種，可複選
  - **帳號**：輸入 Threads 使用者名稱（@ 可省略），抓該帳號的公開貼文
  - **關鍵字**：搜尋公開貼文
  - **hashtag**：依標籤搜尋貼文
  - 每來源文章數 1～200（預設 10），最新排序；可選同步抓每篇的回覆（每篇最多 500 則）
- **蒐集模式（預設「自動（建議）」）**：自動 / 直接網頁 / 隱身瀏覽器 / 官方 Threads API
  - 自動：直接網頁 → 被擋時自動改用隱身瀏覽器 → 再失敗改用官方 Threads API（需先填 Token）。已拿到部分文章就保留並停止，不重複切換。
  - 直接網頁：用 `requests`（403 時 `curl_cffi` 重試一次）抓 threads.com 頁面，從 `<script type="application/json">` 內嵌 JSON 抽出貼文；更多分頁用網站同一款 GraphQL query 加 cursor（`GRAPHQL_DOC_IDS`，doc_id 可能輪換，失敗時會明確寫進執行紀錄，不靜默回空）。單篇貼文頁含文章與第一批回覆。
  - 隱身瀏覽器：Patchright 優先、Camoufox 次之、舊 Playwright 最後備援；優先用你電腦上的真實 Chrome（`channel="chrome"`），沿用登入與 Cookie；人類化捲動（隨機步長、隨機延遲 1–3 秒、偶爾移動滑鼠）；攔截 GraphQL / Relay `__bbox` 回應轉換。第一次使用前按「安裝隱身瀏覽器（自動）」，裝完會立刻重新偵測，不需重開程式。
  - 官方 Threads API：走 `graph.threads.net/v1.0`，需自己申請 Meta App、OAuth、App Review。公開關鍵字搜尋需 `threads_keyword_search` 權限才有，否則只能讀自己的文；**官方 API 沒有熱門／首頁 feed，也無法直接抓他人帳號的貼文**（需 `threads_profile_discovery` 核准），他人帳號請用直接網頁或隱身瀏覽器模式。
- **回覆是樹狀**：用 parent_id 與深度表示，不假裝是樓層。
- **串文標記**：同一作者短時間內連續多則，標記為同一串（`is_continuation`），Excel 與報告中註明。
- **使用者分析**（新增分頁）：輸入 `@帳號`、要抓幾篇發文（預設 50）與幾則回覆他人的留言（預設 100），分開抓兩批再對照，程式先算統計（篇數、平均／中位數長度、emoji 比率、hashtag／mention 比率、發文時段分布、平均愛心／回覆／轉發、常用詞），再用 Gemini 產出 Markdown 風格報告：風格總覽、語氣、寫作風格、主題偏好、互動風格（自己發文 vs 回覆他人對照）、情緒傾向、發文習慣、代表金句、注意事項。報告可存成 MD 檔，Excel 增加「使用者分析」工作表。
  - 注意事項：樣本少於 20 篇時不可靠；風格不等於人格，不是心理測驗；只分析公開帳號；不推斷種族、健康等敏感屬性。
- **Gemini 趨勢分析**：逐篇摘要（40 字內）、分類、情緒、關鍵字，再產生 Markdown 趨勢報告（6 章節、5 種分析角度、統計附錄）。
- **Excel 匯出**：工作表「文章」「留言」「AI趨勢報告」「使用者分析」，深藍標頭、凍結窗格、自動篩選。
- **展示範例資料**：6 篇 Threads 範例文章、12 則回覆，清楚標示 `[展示]`，離線可測試匯出與 AI 流程。

## 安裝與使用

```bash
git clone https://github.com/linhinet7451/thread-analysis-tool.git
cd thread-analysis-tool
pip install -r requirements_threads.txt
python threads_desktop.py
```

1. 在左邊勾選來源（或輸入帳號／關鍵字／標籤按「加入來源」）。
2. 第一次用隱身瀏覽器前，按「安裝隱身瀏覽器（自動）」裝一次就好。
3. 蒐集模式留在「自動（建議）」，按「開始蒐集」。
4. 使用者分析：切到「使用者分析」分頁，輸入帳號，按「開始分析使用者風格」（需先在「AI 趨勢分析」分頁輸入 Gemini API Key）。

## 疑難排解

- **顯示登入牆或 403**：Threads 有登入牆與嚴格限流。先確認模式是「自動（建議）」，工具會自動改用隱身瀏覽器；也可以在瀏覽器登入 Threads 後把 Cookie 貼到設定區（只存記憶體）。不要頻繁重試。
- **直接網頁抓不到文章**：Threads 對一般瀏覽器 UA 只回約 275KB 的空殼頁面，內容全靠 JS 載入；改用隱身瀏覽器模式。
- **自動模式抓不到、還叫你改用自動模式（1.0 的 bug，1.1 已修）**：1.0 版的自動鏈只在直接網頁回 403 時才切換到隱身瀏覽器，但 Threads 最常見的情況是回空殼、0 篇（不是 403），程式就直接停了，還誤導你「請改用自動模式再按一次」——你明明已經在自動模式。1.1 版起，0 篇也會自動切換到隱身瀏覽器；執行紀錄會寫「自動切換到隱身瀏覽器…」。如果切換後仍說尚未安裝，請看執行紀錄確認它偵測到哪個引擎，或重新按「安裝隱身瀏覽器（自動）」。
- **GraphQL 分頁失敗**：網站的 persisted query `doc_id` 會隨改版輪換，執行紀錄會明確寫出原因，改用隱身瀏覽器模式（直接攔截真實請求，不依賴 doc_id）。
- **官方 API 沒有取得文章**：請確認 Token 有效、`threads_keyword_search` 權限已通過 App Review；他人帳號的貼文官方 API 本來就抓不到，請用直接網頁或隱身瀏覽器模式。
- **使用者分析樣本太少**：私人帳號、帳號不存在或登入牆都會抓不到；樣本少於 20 篇時報告會明確寫出可信度較低。
- **「測試 Threads 連線」只測直接網頁**：它失敗不代表工具不能用，自動模式仍會改用隱身瀏覽器。

## 測試

```bash
python3 test_threads.py
```

只測純函式（解析、回覆樹狀、串文標記、使用者統計、風格提示詞、隱身瀏覽器未安裝時的報錯、官方 API 缺 token 時的報錯、展示資料），不發真實 Threads 請求、不啟動瀏覽器。Threads 的即時抓取請在自己的電腦上驗證。

## 隱私與使用條款

- Gemini API Key、Threads Token、Cookie 只存在記憶體，絕不寫入檔案或 Excel。
- 只分析公開帳號與公開貼文；請合理使用、控制頻率，遵守 Threads 使用條款。
- 風格報告是從文字推斷的寫作與互動風格，不是心理測驗，不做人格判定。
